Kế Hoạch Job Đồng Bộ Dữ Liệu Dashboard

Kế hoạch nạp dữ liệu từ collection hiện hữu vào các collection đích được đề xuất trong index.html; riêng widget tổng quan đọc trực tiếp qua dashboard-api

Trạng thái tài liệu: Draft — chưa baseline.

Đây là kế hoạch triển khai dự kiến dựa trên source cũ và snapshot database read-only. Các mapping có nhãn “Decision gate” phải được BE/BA xác nhận trước khi viết job production.

1. Phạm vi & mục tiêu

Mục tiêu triển khai DOC-15 Draft
  • Đọc dữ liệu từ các collection nghiệp vụ hiện hữu.
  • Aggregate theo ngày, tài khoản, loại asset và trạng thái cần thiết cho các read-model của dashboard.
  • Ghi idempotent vào các collection đích: dashboardmissingassets, dashboardinvoicesyncstats và dashboardinvoicecalendar.
  • Không tạo snapshot cho 4 widget tổng quan; các widget này được dashboard-api đọc trực tiếp từ collection nguồn.
  • Không đồng bộ dữ liệu của widget tổng quan sang DB đích; không tạo checkpoint, backfill hoặc reconciliation riêng cho nhóm này.
  • Cung cấp cơ chế backfill, incremental refresh, retry, reconciliation và audit log cho các job read-model.

Phạm vi không bao gồm

  • Không thay đổi dữ liệu nghiệp vụ trong externalaccounts, invoiceraws hoặc externalaccountsyncs.
  • Không copy password, token, cookie, XML, raw body hoặc detail vào bảng đích.
  • Không triển khai API FE/BE trong tài liệu này.
Snapshot đã kiểm tra read-only: database là HDDVLCDev. Các collection read-model được đề xuất trong index.html hiện chưa tồn tại; kế hoạch dưới đây bao gồm bước tạo schema/index trước khi chạy job. Widget tổng quan chỉ đọc trực tiếp và không nằm trong nhóm dữ liệu đồng bộ sang DB đích.

Backfill strategy

  1. Chuẩn hóa mọi ngày theo UTC+7 (Asia/Ho_Chi_Minh).
  2. Chạy thử 1 ngày trên môi trường UAT, ghi source count và target count.
  3. Backfill theo batch ngày hoặc tuần, có checkpoint và giới hạn memory.
  4. Chạy reconciliation sau từng batch trước khi chuyển sang batch kế tiếp.
  5. Chuyển sang incremental job với lookback để bắt late-arriving source record.

4. Job — Missing XML / Detail

dashboard-missing-assets-refresh → dashboardmissingassets Mỗi 30 phút

Aggregate số hóa đơn thiếu XML hoặc Detail theo ngày và trạng thái token. XML và Detail phải được xử lý độc lập.

Query đề xuất

const fromDate = ISODate("2026-08-01T00:00:00.000Z");
const toDate = ISODate("2026-08-08T00:00:00.000Z");

db.getCollection("invoiceraws").aggregate([
  {
    $match: {
      "data.tdlap": { $gte: fromDate, $lt: toDate }
    }
  },
  {
    $lookup: {
      from: "externalaccounts",
      localField: "account",
      foreignField: "_id",
      as: "accountInfo"
    }
  },
  {
    $unwind: {
      path: "$accountInfo",
      preserveNullAndEmptyArrays: true
    }
  },
  {
    $set: {
      hasToken: {
        $and: [
          { $ne: ["$accountInfo.token", null] },
          { $ne: ["$accountInfo.token", ""] }
        ]
      }
    }
  },
  {
    $facet: {
      xml: [
        { $match: { "assets.xml.done": false } },
        { $set: { assetType: "xml" } },
        {
          $group: {
            _id: {
              invoiceDate: {
                $dateToString: {
                  format: "%Y-%m-%d",
                  date: "$data.tdlap",
                  timezone: "Asia/Ho_Chi_Minh"
                }
              },
              assetType: "$assetType",
              hasToken: "$hasToken"
            },
            value: { $sum: 1 }
          }
        }
      ],
      detail: [
        { $match: { "assets.detail.done": false } },
        { $set: { assetType: "detail" } },
        {
          $group: {
            _id: {
              invoiceDate: {
                $dateToString: {
                  format: "%Y-%m-%d",
                  date: "$data.tdlap",
                  timezone: "Asia/Ho_Chi_Minh"
                }
              },
              assetType: "$assetType",
              hasToken: "$hasToken"
            },
            value: { $sum: 1 }
          }
        }
      ]
    }
  }
]);

Kết quả group được upsert vào dashboardmissingassets; không ghi accountInfo.token vào kết quả.

Execution flow

  1. Xác định partition ngày cần chạy từ checkpoint và lookback window.
  2. Chạy hai nhánh filter XML và Detail độc lập.
  3. Join token theo account bằng projection chỉ gồm _id và trạng thái có token.
  4. Group theo invoiceDate + assetType + hasToken, đếm invoiceraws._id.
  5. Upsert target theo unique key invoiceDate + assetType + hasToken.
  6. Xóa hoặc cập nhật lại các bucket của partition khi invoice source đã chuyển sang done = true.

Retry và reconciliation

Trường hợpXử lý / expected result

Query đề xuất

const accountId = ObjectId("66c000000000000000000020");
const fromDate = ISODate("2026-08-01T00:00:00.000Z");
const toDate = ISODate("2026-09-01T00:00:00.000Z");

db.getCollection("invoiceraws").aggregate([
  {
    $match: {
      account: accountId,
      "data.tdlap": { $gte: fromDate, $lt: toDate },
      $or: [
        { from: "query", type: "purchase" },
        { from: "sco-query", type: "purchase" },
        { from: "query", type: "sold" },
        { from: "sco-query", type: "sold" }
      ]
    }
  },
  {
    $set: {
      invoiceDate: {
        $dateTrunc: {
          date: "$data.tdlap",
          unit: "day",
          timezone: "Asia/Ho_Chi_Minh"
        }
      },
      recordType: {
        $switch: {
          branches: [
            { case: { $and: [{ $eq: ["$from", "query"] }, { $eq: ["$type", "purchase"] }] }, then: "purchase" },
            { case: { $and: [{ $eq: ["$from", "sco-query"] }, { $eq: ["$type", "purchase"] }] }, then: "purchase_pos" },
            { case: { $and: [{ $eq: ["$from", "query"] }, { $eq: ["$type", "sold"] }] }, then: "sold" },
            { case: { $and: [{ $eq: ["$from", "sco-query"] }, { $eq: ["$type", "sold"] }] }, then: "sold_pos" }
          ],
          default: null
        }
      }
    }
  },
  { $match: { recordType: { $ne: null } } },
  {
    $group: {
      _id: {
        accountId: "$account",
        month: {
          $dateToString: {
            format: "%m-%Y",
            date: "$invoiceDate",
            timezone: "Asia/Ho_Chi_Minh"
          }
        },
        invoiceDate: "$invoiceDate",
        recordType: "$recordType"
      },
      value: { $sum: 1 }
    }
  },
  { $sort: { "_id.invoiceDate": 1, "_id.recordType": 1 } }
]);

Job pivot các dòng group thành 4 field *Value, sau đó tính monthlyTotal và upsert theo account/tháng/ngày.

Execution flow

  1. Đọc invoiceraws theo account và khoảng ngày bị ảnh hưởng.
  2. Chuẩn hóa data.tdlap thành ngày nghiệp vụ.
  3. Group theo accountId + month + invoiceDate + from + type.
  4. Map sang 4 field count: purchaseValue, soldValue, purchasePosValue, soldPosValue.
  5. Tính monthlyTotal từ tổng 4 loại trong cùng account/tháng.
  6. Upsert theo accountId + month + invoiceDate + recordType = calendar.

Decision cần giữ trong implementation

Source cũ dùng nhánh fallback cho tổ hợp from/type không khớp và gán vào nhóm bán ra máy tính tiền. Dev cần xác nhận có giữ nguyên fallback này hay reject dữ liệu bất thường để tránh làm sai số Calendar.

Query đề xuất

const accountId = ObjectId("66c000000000000000000020");
const lastCheckpoint = ISODate("2026-08-20T00:00:00.000Z");

db.getCollection("externalaccountsyncs")
  .find(
    {
      account: accountId,
      created_date: { $gt: lastCheckpoint }
    },
    {
      _id: 1,
      account: 1,
      created_date: 1,
      ge: 1,
      le: 1,
      total: 1,
      synced: 1,
      created: 1,
      status: 1,
      status_code: 1,
      description: 1
    }
  )
  .sort({ created_date: -1 })
  .limit(100);

Kết quả được upsert theo accountId + sourceSyncId. Bộ lọc theo invoiceDate chưa được thêm vì source hiện chỉ có khoảng ge/le.

Execution flow

  2. Projection các field hiển thị; loại bỏ password, token và config snapshot.
  3. Ghi sourceSyncId = externalaccountsyncs._id vào read-model.
  4. Upsert theo accountId + sourceSyncId.
  5. Expose pagination theo created_date desc.

Query kiểm tra source — chưa dùng để nạp target

const fromDate = ISODate("2026-08-01T00:00:00.000Z");
const toDate = ISODate("2026-08-08T00:00:00.000Z");

db.getCollection("externalaccountsyncs").aggregate([
  {
    $match: {
      created_date: { $gte: fromDate, $lt: toDate }
    }
  },
  {
    $group: {
      _id: {
        date: {
          $dateToString: {
            format: "%Y-%m-%d",
            date: "$created_date",
            timezone: "Asia/Ho_Chi_Minh"
          }
        },
        statusCode: "$status_code"
      },
      sessionCount: { $sum: 1 },
      total: { $sum: { $ifNull: ["$total", 0] } },
      synced: { $sum: { $ifNull: ["$synced", 0] } },
      created: { $sum: { $ifNull: ["$created", 0] } }
    }
  },
  { $sort: { "_id.date": 1, "_id.statusCode": 1 } }
]);

Query này chỉ cho thấy các dimension hiện có của source. Không được dùng trực tiếp để ghi dashboardinvoicesyncstats trước khi chốt mapping status và ngày.

Execution flow

  1. Job khởi động ở trạng thái disabled.
  2. BE/BA ký mapping status và date dimension.
  3. Viết test fixture cho từng status và trường hợp thiếu field.
  4. Chạy UAT một partition ngày, đối chiếu với màn hình cũ hoặc số liệu được xác nhận.
  5. Chỉ sau khi reconciliation đạt mới bật scheduler 30 phút.
